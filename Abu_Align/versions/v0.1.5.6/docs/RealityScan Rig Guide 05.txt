Please update the XMP export template in the 360 splitter script with the following changes to eliminate alignment crashes in RealityScan:

### 1. Remove Hardware Rig Tags
Remove these three lines completely:
- `xcr:Rig="..."`
- `xcr:RigInstance="..."`
- `xcr:RigPoseIndex="..."`
(Without an external XML rig calibration definition, using RigPoseIndex causes null-pointer crashes and singular matrix errors in the bundle adjustment solver.)

### 2. Lock Rigid Groups via LockedPoseGroup
Use `xcr:LockedPoseGroup="{FRAME_INTEGER_INDEX}"` as an attribute of `<rdf:Description>` so that all 6 cube faces of the same frame (e.g., frame 003 = 3) are mathematically constrained as a rigid cluster.

### 3. Set Pose Prior & Accuracies
- Change `xcr:PosePrior="exact"` to `xcr:PosePrior="approximate"`.
- Add positional and rotational accuracy child elements inside `<rdf:Description>` to allow the 10–30 cm trajectory error to be resolved:
  <xcr:PoseAccuracyPosition>0.300000 0.300000 0.300000</xcr:PoseAccuracyPosition>
  <xcr:PoseAccuracyRotation>0.001000 0.001000 0.001000</xcr:PoseAccuracyRotation>

### 4. Target XMP Template:
```xml
<x:xmpmeta xmlns:x="adobe:ns:meta/">
  <rdf:RDF xmlns:rdf="[http://www.w3.org/1999/02/22-rdf-syntax-ns#](http://www.w3.org/1999/02/22-rdf-syntax-ns#)">
    <rdf:Description xmlns:xcr="[http://www.capturingreality.com/ns/xcr/1.1/](http://www.capturingreality.com/ns/xcr/1.1/)"
      xcr:Version="3"
      xcr:PosePrior="approximate"
      xcr:Coordinates="absolute"
      xcr:LockedPoseGroup="{FRAME_INTEGER_INDEX}"
      xcr:CalibrationGroup="1"
      xcr:DistortionGroup="1"
      xcr:CalibrationPrior="locked"
      xcr:LensDistortionPrior="locked"
      xcr:DistortionModel="brown3"
      xcr:FocalLength35mm="11.689337"
      xcr:Skew="0.000000"
      xcr:AspectRatio="1.000000"
